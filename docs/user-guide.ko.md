## 1. 설치와 첫 실행

다운로드와 SHA-256 확인 방법은 [README](../README.ko.md#다운로드)에 있습니다.

- **설치 파일** — `LumiPilot-<버전>-build<N>-windows-x64-setup.exe`를 실행합니다. 관리자 권한이 필요 없고 현재 사용자에게만 설치합니다. 제거는 Windows 설정 → 앱에서 합니다.
- **포터블 ZIP** — 원하는 곳에 풀고 `LumiPilot.exe`를 실행합니다. 설치 과정이 없습니다.

처음 실행하면 이용·안전 안내가 나옵니다. 언어(한국어/English)를 고르고 내용을 확인하세요. 이어서 AI 연결 설정 창이 뜹니다(2장).

### 데이터 위치

앱이 폴더를 자동으로 만듭니다. 제거해도 지워지지 않습니다.

| 항목 | 위치 |
|---|---|
| 데이터 폴더 | `%APPDATA%\LumiPilot\LumiPilot` |
| 설정 | `config\settings.ini` |
| 대화·기억·예약 | `data\` |
| 로그 | `data\log\app.log` |
| 오류 기록 | `data\CrashLogs\` |

## 2. 처음 설정

### 2-1. 프로바이더와 모델 고르기

처음 실행 때는 **AI 연결 설정** 창이 먼저 뜹니다. 쓸 화면(코딩 세션/캐릭터 세션)과 서비스·인증·모델을 한 번에 고르고 **시작하기**를 누릅니다. **나중에 설정**으로 닫았다면 설정 → API → **AI 연결 설정**으로 다시 열 수 있습니다.

- **프로바이더** — 쓸 AI 서비스를 고릅니다.
  - API 키로 쓰는 것: Anthropic, OpenAI, Google Gemini, xAI, NVIDIA, Z.ai, OpenRouter, OpenCode, Ollama(내 컴퓨터에서 실행), 직접 추가하는 OpenAI 호환 엔드포인트
  - 구독 계정으로 로그인해 쓰는 것: ChatGPT, Grok, GitHub Copilot. 허용 여부는 각 프로바이더의 약관을 따릅니다.
  - Claude와 Gemini의 **구독 로그인은 이 버전에서 막혀 있습니다.** 두 서비스도 API 키로는 쓸 수 있습니다.
- **모델** — 고른 프로바이더의 모델을 고릅니다. 목록이 비어 있으면 **↻** 버튼으로 받아옵니다. API 키를 아직 넣지 않았으면 안내가 뜹니다.
- **보조 모델**(선택) — 제목 만들기·기억 정리 같은 가벼운 일에 쓸 저렴한 모델입니다. 비워 두면 위에서 고른 모델을 따릅니다.

### 2-2. API 키 넣기

**설정 → API** 탭에서 넣습니다. 쓰려는 기능의 키만 넣으면 되고, 입력하는 즉시 저장됩니다(저장 버튼이 없습니다).

| 항목 | 언제 필요한가 |
|---|---|
| API 키로 쓰는 프로바이더 | API 키 방식 프로바이더를 골랐을 때 |
| 구독으로 쓰는 프로바이더 | 구독 계정으로 로그인할 때(버튼을 누르면 안내가 뜹니다) |
| 사용자 정의 프로바이더 | 사내 게이트웨이 같은 OpenAI 호환 주소를 붙일 때 |
| 이미지 생성 | AI에게 그림을 그리게 할 때 |
| Google Workspace | Gmail·캘린더·Drive·Tasks를 쓸 때(본인의 Google OAuth 클라이언트 필요) |
| 메일 계정 | 회사·인터넷 메일(IMAP/SMTP)을 쓸 때 |
| 웹 검색(Tavily) | AI가 인터넷 검색을 할 때 |
| LINE | AI가 LINE 메시지를 보낼 때 |
| 음성(ElevenLabs) | 음성 모델 방식으로 소리 내어 말할 때 |
| git 토큰 | AI가 원격 저장소를 복제·푸시할 때(직접 입력 또는 GitHub 로그인) |

같은 화면 맨 아래 **기기 간 이전**으로 키를 파일로 내보내 다른 PC로 옮길 수 있습니다. 내보낸 파일은 암호화되지 않으니 옮긴 뒤 반드시 지우세요. 구독 로그인 정보는 파일에 들어가지 않으니 새 PC에서 다시 로그인합니다.

### 2-3. 작업 폴더 정하기

**설정 → 일반 → 작업 환경 → 작업 폴더 → 변경**. AI가 파일을 읽고 고치고 명령을 실행할 때의 기준 폴더입니다. 이 폴더가 AI의 작업 범위라고 생각하세요. 단, 이것이 격리 장치는 아닙니다(5장).

### 2-4. 알림과 음성(선택)

- **작업 완료 알림**(설정 → 일반) — 앱을 보고 있지 않을 때 백그라운드 작업 완료를 알립니다.
- **음성 출력**(설정 → 일반) — 읽는 방식을 고릅니다. **OS 내장 TTS**는 별도 키 없이 PC에 설치된 목소리로 읽고, **음성 모델**은 음성 키(API 탭)가 필요하며 글자 수만큼 요금이 듭니다. **코딩 세션 답변 읽기**를 켜면 보고 있는 대화의 최종 답변도 읽습니다. 도구 출력·생각 과정·코드 블록은 읽지 않으며, 한 답변에 최대 4,000자까지 읽습니다.

## 3. 화면 둘러보기

### 위쪽 바

왼쪽부터 다음과 같습니다.

- **☰** — 사이드바를 엽니다.
- **세션 이름 알약** — 지금 보고 있는 대화의 이름입니다. **누르면 컨텍스트 사용률 창**이 열립니다(6장). AI가 답하는 중이면 왼쪽 점이 깜빡입니다.
- **칸 나누기 버튼**(넓은 화면) — 대화 칸을 2~3개 나란히 엽니다.
- **세션 목록 버튼** — 대화 목록과 보관함을 엽니다. 열려 있는 대화 수가 보이고, 다른 대화가 응답을 기다리면 점이 뜹니다.
- **변경 배지** — 작업 폴더에 아직 커밋하지 않은 변경이 있으면 개수가 뜹니다. 누르면 파일 관리자의 "변경 사항" 탭이 열립니다.
- **브라우저 버튼** — 앱 안의 웹 브라우저를 엽니다.

캐릭터 화면에서는 가운데에 **맡긴 세션** 요약이 대신 뜹니다.

### 사이드바(☰)

- **찾기** — 대화 검색. 결과는 대화별로 묶이고, 결과를 누르면 그 메시지로 이동해 잠깐 강조합니다.
- **프로바이더 / 모델 / ↻** — 2장 참고. 캐릭터 화면에서는 캐릭터 모델 설정(대화 모델·등급별 모델·음성)이 이 자리에 나옵니다.
- **보조 모델** — 경량 모델을 따로 지정합니다(제목·메모리·완료 판정 등). 압축 요약은 기본 모델이 합니다.
- **트리거** — 매크로·트리거 기능 전체를 켜고 끕니다.
- **아래 아이콘 줄** — 찾기 · 파일 · 캐릭터 · 설정. 캐릭터 버튼은 코딩 화면과 캐릭터 화면을 전환합니다.
- 맨 아래에 앱 버전이 표시됩니다.

### 파일 관리자(사이드바 → 파일)

탭이 셋입니다.

- **파일 탐색** — 작업 폴더의 파일을 봅니다. 이름 걸러 보기, 정렬(이름·수정 시각·크기), 숨김 파일 표시, 새 폴더 만들기, 원격 주소로 저장소 복제(＋클론), 드라이브 전환, 작업 폴더로 돌아오기를 지원합니다. 파일이나 폴더를 우클릭하면 **이동 · 실행 · 이름 변경 · 복사본 만들기 · 경로 복사 · 작업 폴더로 설정(폴더) · 삭제** 메뉴가 뜹니다. 파일을 누르면 내용 뷰어가 열립니다(줄 바꿈, 안에서 검색, Markdown 보기, 글자 크기 조절). 큰 파일은 나눠서 읽고, 그림·실행 파일은 크기와 형식만 보여 줍니다. HTML은 스크립트와 외부 통신을 막은 정적 미리보기로 먼저 그려 보고, **보기**를 누르면 앱 안 브라우저에서 스크립트까지 실행합니다. 미리보기 한도는 이미지 32MiB, HTML 8MiB입니다.
- **변경 사항** — 아직 커밋하지 않은 변경을 봅니다. 파일을 골라 **스테이지/해제**, **변경 버리기**를 하고, 커밋 메시지를 적어 커밋합니다. 위쪽 버튼으로 **가져오기(fetch) · 풀(pull) · 푸시(push)** 합니다. 원격 작업은 확인 창을 거치고, 실패하면 이유가 알림으로 표시됩니다. 충돌이나 병합 진행 중 상태도 여기에 나옵니다.
- **커밋 기록** — 커밋 목록입니다. 커밋을 누르면 바뀐 파일과 차이를 볼 수 있고, 원격에만 있는 커밋은 **받기**로 내려받습니다.

### 브라우저

사람과 AI가 **같은 탭**을 함께 씁니다. 위쪽에 뒤로·앞으로·새로고침·중지·새 탭과 주소창이 있고, **더보기** 메뉴에 **외부 브라우저로 열기 · AI에게 이 탭 맡기기**가 있습니다. **AI에게 맡기면 AI가 그 페이지를 조작**합니다(클릭·입력·읽기).

- 탭은 최대 3개입니다. 넘치면 가장 오래 안 쓴 탭부터 닫힙니다.
- 내가 로그인한 사이트는 AI도 로그인된 상태로 씁니다. 앱은 사이트 비밀번호를 저장하지 않고, 내가 직접 로그인해 생긴 로그인 상태(쿠키)만 앱 전용 프로필에 남습니다.
- 화면이 넓으면 대화 오른쪽에 브라우저 창이 함께 뜹니다(경계를 끌어 크기를 조절하고 접을 수 있습니다).
- 페이지가 확인창·입력창·알림을 띄우면 앱 안에서 그대로 답합니다.
- 브라우저 기능에는 Microsoft Edge WebView2 런타임이 필요합니다.

## 4. 대화하기

아래쪽 입력창에 적고 **전송**(종이비행기 버튼)을 누릅니다. **Enter**로 보내고 **Shift+Enter**로 줄을 바꿉니다. 새 대화에는 "무엇을 도와드릴까요?" 안내가 뜨고, 첫 메시지를 보내면 사라집니다.

### 입력창 버튼

- **모드 버튼(슬라이더 모양)** — 실행 권한과 계획 모드를 바꿉니다(아래 참고).
- **첨부(클립)** — 그림을 붙입니다. 그림을 받는 모델일 때만 보입니다. 화면 캡처를 붙여넣어도 됩니다.
- **명령어(/)** — `/` 명령 목록을 열어 고릅니다.
- **낭독 중지** — 음성 출력이 읽는 중일 때만 보입니다.

### 보내는 중에

AI가 답하는 동안에는 다음을 할 수 있습니다.

- **중지(네모)** — 그만두게 합니다.
- **글을 적고 보내면 스티어** — 지금 하는 일에 "이렇게 해 줘"를 끼워 넣습니다.
- **대기 줄** — 답하는 중에 보낸 말은 아래에 쌓였다가 끝나면 이어서 전달됩니다(최대 5개). 끌어서 순서를 바꾸거나 눌러서 고칠 수 있습니다.

### 모드 버튼

버튼 테두리 색으로 지금 상태를 알 수 있습니다. 여기서 바꾼 값은 **이 대화에만** 적용됩니다.

- **계획 모드** — AI가 바로 고치지 않고, 먼저 "이렇게 하겠다"는 계획을 보여 주고 허락을 받습니다. 답하는 중에는 켜고 끌 수 없습니다.
- **실행 권한** — 세 단계입니다. 새 대화의 기본값은 **편집 전 확인**입니다.
  - **편집 전 확인**(회색) — 파일을 고치거나 명령을 실행할 때 규칙과 위험 등급에 따라 승인을 요청합니다.
  - **자동 편집**(초록) — 파일 편집은 자동, 나머지는 별도 규칙에 따라 묻습니다.
  - **전체 자동**(빨강) — 명시적으로 거부한 것을 빼고는 묻지 않고 실행합니다.
- **추론 강도** — AI가 얼마나 깊게 생각할지 정합니다. 높을수록 똑똑하지만 느립니다. 모델이 지원하는 단계만 보입니다.
- **압축 시점** — 대화가 이 비율을 넘으면 오래된 부분을 요약해 자리를 비웁니다.
- **적극 위임** — 켜면 시키지 않아도 AI가 일을 나눠 여러 도우미에게 맡깁니다.

### 특수 명령

- `/goal 할 일` — 대화에 **목표**를 겁니다. AI가 목표를 이룰 때까지 스스로 이어서 일하고 다 됐는지 확인합니다. 입력창 위에 목표 칩이 생깁니다. 칩에는 상태(진행 중·완료·일시정지·막힘·사용량 제한·예산 도달)와 사용 토큰·시간이 보이며, 눌러서 **상세 보기 · 수정 · 일시정지/재개 · 해제**를 합니다. 중단된 목표가 있으면 앱을 다시 켜거나 그 대화를 열 때 재개할지 묻습니다.
- `/compact` — 오래된 대화를 지금 요약해 자리를 비웁니다. 다른 글 없이 이것만 입력합니다.

목표 표식을 켠 뒤에는 **Esc**나 표식의 ✕로 일반 입력으로 돌아갑니다.

### 대화에 뜨는 카드

AI가 일하는 동안과 끝난 뒤에 카드가 뜹니다. 대부분 눌러서 펼칠 수 있고, 우클릭하면 복사 같은 메뉴가 뜹니다. 긴 출력은 **▼ 펼치기**로 전부 볼 수 있습니다.

- **작업 카드** — AI가 실행한 도구(파일 읽기·검색·명령 등)를 묶어 보여 줍니다. 실패한 개수도 표시됩니다. 셸 명령은 **실행 명령**과 **실행 결과**로 나뉩니다.
- **파일 편집 카드** — 고친 내용을 차이(diff)로 보여 줍니다. **분할/인라인**으로 보기 방식을 바꿉니다.
- **HTML 카드** — 차트·문서 같은 결과물을 바로 그려 보여 줍니다. 미리보기/코드 보기 전환, 전체 화면, HTML로 저장, 브라우저로 열기가 있습니다.
- **그림 카드** — AI가 그린 그림입니다. 눌러서 크게 보고, **경로 복사 · 기본 앱으로 열기 · 영역 주석**을 할 수 있습니다. 영역 주석은 고칠 부분을 드래그해 설명을 달면 그대로 수정 요청이 됩니다.
- **도우미 카드** — AI가 일을 나눠 맡긴 도우미(서브에이전트)입니다. 펼치면 각 단계가 보입니다.
- **할 일 카드** — AI가 세운 작업 목록과 진행률입니다.
- **질문 · 기억 · 알림 카드** — AI가 물어본 것과 답, 기억해 둔 내용, 압축·계획 승인 같은 알림입니다.
- **리뷰 카드** — AI가 코드를 살펴 찾은 문제 목록입니다. 항목에서 **입력창에 넣기**(수정 요청 문구를 입력창에 채움)나 **자동 수정**을 쓸 수 있습니다.
- **오류 카드** — 문제가 생기면 이유와 **↺ 재시도** 버튼이 뜹니다.
- **완료 카드** — 백그라운드 작업이 끝나면 뜹니다(10장).

### AI가 물어볼 때

AI가 선택지를 물으면 입력창 자리에 **선택 창**이 뜹니다. 항목을 고르거나 **기타(직접 입력)** 로 쓴 뒤 **제출**합니다. **취소**하면 그 질문을 건너뜁니다. 처리할 요청이 여러 개면 입력창 위에 "대기 중인 요청 n건 더"가 뜨고, 하나씩 처리하면 다음 것이 올라옵니다.

## 5. 승인과 안전

AI가 무언가를 바꾸려 하면(파일 고치기, 명령 실행, 메시지 보내기 등) 실행 직전에 **승인 창**이 뜹니다. 창에는 무엇을 하려는지와 위험이 적혀 있고, 명령이면 **어느 셸**(PowerShell·bash)로 실행되는지도 보입니다.

- **실행**(파일 편집은 **적용**) — 이번만 허락합니다.
- **거부** — 하지 못하게 합니다.
- **중지** — 그 작업 자체를 그만둡니다.

같이 켤 수 있는 기억 규칙입니다. 누르면 다음부터 다시 묻지 않습니다.

- **이 명령 패턴 항상 허용** — 자주 쓰는 명령을 기억합니다(설정 → 일반 → 허용된 셸 명령에서 관리).
- **이 폴더 편집 항상 허용** — 그 폴더의 파일 고치기를 기억합니다.
- **이번 세션 동안 허용** — 화면 보기, 브라우저, 마우스·키보드 조작처럼 넓은 작업에 씁니다.

**계획 모드**에서 계획을 검토할 때는 이어가는 방법을 고릅니다.

- **승인·단계 확인** — 계획대로 하되 단계마다 다시 확인합니다.
- **승인·편집 자동** — 이 계획은 편집을 자동으로 진행합니다.
- 거부할 때 무엇을 바꿀지 적으면 AI가 계획을 고쳐 다시 가져옵니다.

### 꼭 알아 두세요

- **샌드박스가 아닙니다.** 승인한 명령과 도구는 사용자 계정 권한 그대로 실행됩니다. 작업 폴더 지정과 승인 창은 OS 수준 격리가 아닙니다. 관리자 권한으로 실행하지 말고, 위험한 작업은 사본에서 먼저 해 보세요.
- **"항상 허용"은 이후에도 재사용됩니다.** 같은 인자의 1회 승인과 다릅니다. 승인 창의 대상·내용·허용 범위를 확인하세요. 전체 자동은 신뢰하는 시험 환경에서 쓰세요.
- **외부 자료에 속지 마세요.** 웹페이지·메일·저장소 지침·도구 결과에 악의적인 지시가 섞여 있을 수 있습니다. 비밀 읽기·권한 확대·외부 전송을 요청하면 목적과 대상을 확인하세요.
- **거부·중지는 이미 끝난 일을 되돌리지 않습니다.** 완료된 파일 변경·명령·외부 발송과 비용은 그대로입니다.

## 6. 대화 관리

### 대화 목록

- **새 대화** — 목록 맨 위에 있습니다. 동시에 열어 둘 수 있는 대화는 최대 30개입니다.
- **이름 바꾸기** — 대화 옆 연필(✎)을 누릅니다. 자동 제목을 켜 두면 첫 답변 뒤에 제목이 붙습니다.
- **옆에 열기(▥)** — 칸 나누기를 쓸 수 있는 화면에서 그 대화를 옆 칸에 엽니다.
- **닫기(✕)** — **취소 · 보관 · 영구 삭제** 중에 고릅니다. 보관하면 "보관함"에 남아 나중에 되살릴 수 있습니다. 영구 삭제는 되돌릴 수 없습니다.
- **보관함** — 목록 아래쪽에 있습니다. 항목을 누르면 되살아나고, 휴지통을 누르면 영구 삭제됩니다.

### 세션 칸 나누기(넓은 화면)

위쪽 바의 **칸 나누기** 버튼으로 대화 칸을 2~3개 나란히 엽니다. 칸마다 대화와 입력창이 있습니다. 빈 칸에서는 열 대화를 고르거나 **새 대화**를 엽니다.

- 폭이 모자라면 먼 칸부터 세로 레일로 접히고, 레일을 누르면 다시 펴집니다.
- 칸 머리의 ✕는 **칸만 닫습니다**(대화는 남습니다).
- 칸 경계를 끌어 폭을 조절하고, 더블클릭하면 균등 배분으로 돌아옵니다. 배치는 앱을 다시 켜도 복원됩니다.
- 단축키: **Ctrl+\\** 칸 나누기 · **Ctrl+1/2/3** 그 칸 선택 · **Ctrl+Shift+W** 선택 칸 닫기.
- 칸에 승인·질문이 기다리면 칸 머리에 상태(승인 대기·질문·실패)가 뜹니다.

### 컨텍스트 사용률

세션 이름 알약을 누르면 이 대화가 AI의 대화 창을 얼마나 차지하는지 보입니다. 메시지·도구 정의별 사용량, 최대 창, 압축이 일어나는 시점, 프롬프트 재사용으로 아낀 양이 나옵니다. 구독 요금제를 쓰면 프로바이더가 알려 준 요금제 사용률(창별 사용률과 초기화 시각)도 함께 보입니다. GitHub Copilot은 월 한도 사용률이 보입니다. 자리가 부족하면 `/compact`로 지금 요약하세요.

### 메시지 되돌리기

메시지를 우클릭하면 메뉴가 뜹니다.

- **복사 / 선택 복사**
- **편집** — 내가 보낸 메시지를 고쳐 다시 보냅니다. 보내면 그 뒤 대화는 지워지고 다시 진행됩니다.
- **펼치기 / 접기** — 긴 메시지를 접거나 폅니다.
- **파일 되돌리기** — 그 메시지 이후 AI가 고친 파일을 원래대로 되돌립니다(체크포인트). 확인 창이 뜨고, 결과(복원·삭제·건너뜀)를 알려 줍니다.

체크포인트 한계:

- 앱이 지원하는 파일 편집 경로로 바뀐 파일만 기록합니다. 셸 명령, 외부 프로그램, DB, 메일, 원격 서버의 변경은 복구하지 않습니다.
- 파일당 4MiB를 넘는 원본은 기록하지 않습니다. 세션 기록이 64MiB를 넘으면 오래된 턴부터 정리하고, 정리된 턴으로 되돌릴 때 그 파일은 복원할 수 없다고 표시합니다.
- 복원은 현재 파일을 덮어쓰거나 새로 만든 파일을 지울 수 있습니다. 앱 밖에서 고친 내용이 자동으로 보호되지 않으니, 복원 전에 변경을 검토하세요.
- 체크포인트는 별도 백업을 대신하지 않습니다.

## 7. AI가 할 수 있는 일

AI는 상황에 맞는 도구를 스스로 골라 씁니다. 사용자가 외우거나 부를 필요는 없습니다. 도구 대부분은 승인 규칙(5장)을 따릅니다.

- **파일과 코드** — 파일 읽기·쓰기·고치기(`apply_patch` 포함), 파일 이름·내용 검색, 코드 심볼 찾기, 오류 확인.
- **명령과 Git** — 터미널 명령 실행, 오래 걸리는 일의 백그라운드 실행, 조건이 될 때까지 반복 실행, Git 상태·커밋·병합·푸시.
- **계획과 도우미** — 할 일 목록, 오래 걸리는 일을 여러 도우미(서브에이전트)에게 나눠 맡기기, 사용자에게 질문하기.
- **기억과 예약** — 중요한 사실 기억, 알림, 반복 예약, 나중에 다시 깨우기.
- **화면과 웹** — 화면 캡처, 마우스·키보드 조작, 앱 창 조작(Windows), 웹 검색, 웹 페이지 읽기, 앱 안 브라우저 조작, 외부 브라우저로 열기. **화면에 보이는 모든 앱 내용이 AI에게 전달**되므로, 승인 창의 경고를 읽고 허락하세요.
- **그림과 문서** — 그림 그리기(이미지 생성 설정 필요), 차트 같은 HTML 결과물 만들기.
- **Google** — 캘린더·Tasks·Drive·Docs. 설정 → API에서 본인의 Google OAuth 클라이언트로 계정을 연결해야 합니다. 일정·메일·할 일 도구는 캐릭터 세션에서만 쓰고, Drive·Docs는 코딩 세션에서도 씁니다.
- **메일** — 연결한 계정(Gmail, 설정에서 등록한 IMAP/SMTP)에서 메일 읽기, 초안 저장, 발송, 휴지통 이동·복원, 스팸 정리.
  - 보내기·삭제·스팸 지정은 항상 내용을 보여 주고 승인을 받으며, "이번 세션 동안 허용"은 나오지 않습니다. 삭제는 휴지통 이동이라 되돌릴 수 있습니다.
  - 회사·인터넷 메일은 설정 → API → 메일 계정에서 추가합니다. 받는 서버(IMAP)와 보내는 서버(SMTP)의 주소·포트·보안 방식을 넣고 **연결 시험**으로 둘을 따로 확인한 뒤 저장합니다. 연결은 항상 TLS이고, 인증서가 맞지 않으면 로그인 정보를 보내지 않습니다. 네이버·다음처럼 앱 비밀번호가 필요한 서비스도 있습니다.
  - **메일 본문을 AI에게 보내도 되는지는 계정마다 골라야 하며 기본값이 없습니다.** "허용 안 함"이면 AI는 제목·발신자·날짜만 봅니다.
  - 서버에 초안을 둘 수 없는 계정은 초안을 이 PC에만 저장합니다. 서버가 안전한 이동(MOVE 또는 UIDPLUS)을 지원하지 않으면 정리 기능만 꺼지고 읽기·발송은 됩니다.
- **메신저** — LINE 메시지 보내기.

### Windows 전용: 크래시 분석과 Visual Studio 디버깅

프로그램이 멈추거나 죽었을 때 원인 찾기를 AI에게 맡길 수 있습니다. AI는 읽기만 하고 프로그램을 멈추거나 고치지 않습니다.

- **크래시 덤프 분석** — `.dmp` 파일 경로를 알려 주면("이 크래시 원인을 찾아 줘") 함수·소스 줄·GPU 관련 증거까지 읽어 알려 줍니다. 분석기(`LumiPilotDumpAnalyzer.exe`)가 함께 들어 있어 **Visual Studio가 없어도 됩니다.**
- **Visual Studio 라이브 조회**(선택) — Visual Studio에서 프로그램이 중단점·예외로 멈춰 있을 때 스레드·스택·변수 값을 읽습니다. 확장 설치가 필요합니다. **Visual Studio를 모두 닫고** 압축을 푼 폴더의 `extras\LumiPilotDebugBridge.vsix`를 실행한 뒤(Visual Studio 2022·2026) 다시 엽니다. 설치 확인은 Visual Studio의 **출력(Output) 창 → "LumiPilot Debug Bridge"**에서 합니다. 확장은 읽기 전용이라 중단점 추가, 계속·단계 실행, 변수 변경, 함수 호출을 하지 않습니다. 서명이 없어 설치 창이 경고할 수 있습니다.

## 8. 루미(캐릭터)

루미는 앱에 들어 있는 캐릭터이자 말벗입니다. 코딩 도구를 직접 쓰지 않고, 대신 **대화에 일을 맡깁니다.** 다른 캐릭터를 가져오거나 고르는 기능은 없습니다. 사이드바의 **캐릭터** 버튼으로 캐릭터 화면으로 전환합니다.

- **대화** — 입력창에 말을 걸면 루미가 답합니다. 지금까지의 대화가 늘 보이고, 말을 길게 누르면 "다시 듣기 / 다시 보내기"가 가능합니다.
- **캐릭터 설정**(입력창의 모드 버튼) — 맡긴 일을 계획부터 세울지, 세션 승인 단계, 동시에 시킬 개수, 추론 강도, 중간 보고 여부를 정합니다.
- **일 맡기기** — "이 저장소에서 버그를 고쳐 줘"처럼 시키면 루미가 코딩 세션을 열어 일을 맡깁니다.
  - 화면 위쪽에 맡긴 일과 상태(작업 중·허락 기다림·답 기다림·실패·멈춤·끝남)가 보입니다. 누르면 목록이 열리고 **채팅에서 보기 · 등급 바꾸기 · 멈추기**를 할 수 있습니다.
  - 루미는 일의 크기(큰 일·보통 일·가벼운 일)에 맞는 모델을 골라 씁니다. 등급별 모델은 캐릭터 화면의 ☰ → 캐릭터 모델 설정에서 정합니다.
  - 맡긴 일이 승인을 기다리면 입력창 위에 한 줄로 뜹니다. **펼치기**로 내용을 보고 버튼이나 말로 답하세요. 거부하면 그 일은 중단됩니다.
- **음성** — 설정 → 일반의 **음성 출력**에서 켭니다(2-4).
- **다음 일정 카드** — 앞으로의 일정을 시각순으로 최대 3건 보여 줍니다. 캐릭터 예약과 Google 캘린더(기본 캘린더) 일정이 함께 나오고, 줄마다 출처가 적힙니다. 카드를 누르면 예약 창이 열립니다. Google 조회가 실패하면 마지막 성공 기준으로 보여 주고 "조회 실패"를 함께 적습니다.
- **할 일** — 일정 아래의 "할 일 N개 남음"을 누르면 Google Tasks 팝업이 열립니다. 추가·수정·완료·삭제는 루미에게 요청하며 기존 승인 규칙을 거칩니다. 설정 → API의 Google 연결에서 **할 일 권한 추가**를 눌러 같은 계정을 선택하고, Google Cloud에서 Tasks API를 켜야 합니다.
- **예약** — 말로 만들거나(`매일 아침 8시에 브리핑해 줘`) 설정 → 캐릭터에서 추가합니다. 알림 / 질문 / 일 맡기기 중에 고르고, 반복은 한 번·매일·평일·매주·간격으로 정합니다. 앱이 꺼져 있던 동안 지난 예약은 다음에 켤 때 한 번 알려 줍니다.
- **아침 브리핑·먼저 말 걸기** — 오늘 일정, 안 읽은 메일, 날씨, 밤사이 끝난 작업 결과를 알려 줍니다. "용건이 없어도 먼저 안부 건네기"를 켜면 정해 둔 시간대에 먼저 말을 겁니다. 이 기능들은 **앱이 켜져 있을 때만** 동작합니다.

앱의 루미 캐릭터와 아이콘에는 AI로 만든 시각 자산이 쓰였고, 답변·생성 이미지·합성 음성은 AI가 만든 결과로 표시됩니다.

### 메모리

### 스킬

AI가 따르는 절차 모음입니다. AI에게 만들어 달라고 하거나, 공개 GitHub 저장소에서 설치하거나, 마크다운 파일로 직접 만들어 등록할 수 있습니다. 설정 → 스킬 탭에는 불러온 스킬이 출처(기본 제공 · 사용자 스킬 · 작업폴더 · 플러그인)와 함께 나열되고, 스킬마다 켜기/끄기 스위치, 적용 조건(운영체제·프로바이더) 표시, 불러오기 경고가 보입니다. 파일을 고친 뒤에는 **스킬 다시 읽기**를 누릅니다.

**AI에게 맡기기**

기본 제공 스킬 `skill-creator`와 `skill-installer`가 있어, 코딩 세션(작업 폴더를 연 대화)에서 말로 시키면 됩니다. Python이나 Git을 따로 설치하지 않아도 됩니다.

- **스킬 만들기** — "릴리즈 노트를 쓰는 스킬을 만들어 줘"처럼 요청합니다. AI는 기존 스킬로 충분한지 먼저 보고, 저장 위치를 정해 `SKILL.md`를 쓰고, 형식 검사까지 마칩니다. 위치는 기본이 이 프로젝트(`.agents\skills\`)이고, 모든 프로젝트에서 쓰려면 그렇게 요청하세요(사용자 스킬 폴더). 만든 스킬은 다음 턴부터 쓸 수 있습니다.
- **GitHub에서 설치하기** — "github.com/소유자/저장소 에서 스킬 설치해 줘"처럼 저장소를 알려 줍니다. AI가 저장소의 스킬 목록을 보여 주면 하나를 고르고, 이 프로젝트용인지 모든 프로젝트용인지 정합니다. 설치 직전에 **승인**을 묻습니다.
  - 공개 저장소만 됩니다. 설치는 목록을 읽은 시점의 커밋(40자리 해시)에 고정되어, 같은 요청은 항상 같은 파일을 설치합니다.
  - 받기 전에 파일 목록을 검사해 심볼릭 링크, 하위 모듈, 실행 파일(`.exe`·`.dll` 등), 500개 또는 20MB를 넘는 묶음을 거절합니다. `SKILL.md`가 적재할 수 없는 형식이면 아무것도 설치하지 않고, 쓰다가 실패하면 쓴 파일을 되돌립니다.
  - 같은 이름의 스킬이 이미 있으면 덮어쓰지 않습니다. 새 버전을 받으려면 기존 폴더를 직접 지운 뒤 다시 설치하세요.
  - GitHub의 비로그인 요청 한도(시간당 60회)를 넘으면 다시 시도할 수 있는 시각을 알려 줍니다.
  - 설치한 스킬은 외부에서 온 지침입니다. 쓰기 전에 `SKILL.md`와 들어 있는 스크립트를 읽어 보세요. 아래 **스킬 쓰기**의 주의가 그대로 적용됩니다.

**직접 등록하기**

1. **폴더를 고릅니다.** 앱은 아래 두 곳(과 기본 제공·플러그인 스킬)만 읽습니다. 폴더가 없으면 직접 만듭니다.

   | 범위 | 위치 |
   |---|---|
   | 사용자 스킬(모든 프로젝트) | `%APPDATA%\LumiPilot\LumiPilot\config\skills\` |
   | 작업폴더 스킬(그 프로젝트만) | `<작업 폴더>\.agents\skills\` |

   이름이 같으면 작업폴더 → 사용자 → 플러그인 → 기본 제공 순으로 앞의 것이 우선합니다. Claude Code의 `.claude\skills\`와 작업 폴더의 `skills\`는 읽지 않으니, 쓰던 스킬은 위 폴더로 복사하세요.

2. **스킬 폴더와 `SKILL.md`를 만듭니다.**

   ```text
   .agents\skills\
   └─ release-notes\          ← 폴더 이름 = 스킬 이름
      ├─ SKILL.md             ← 필수
      ├─ references\          ← 필요할 때만 읽을 상세 문서(선택)
      ├─ scripts\             ← 반복 실행할 도구(선택)
      └─ assets\              ← 결과물에 복사할 파일(선택)
   ```

   `SKILL.md`는 맨 위에 `---`로 감싼 머리말을 두고, 그 아래에 지침 본문을 적습니다.

   ```markdown
   ---
   name: release-notes
   description: 릴리즈 노트를 쓸 때 사용한다. 단순 커밋 목록 요약에는 사용하지 않는다.
   ---

   # 릴리즈 노트 작성

   1. 마지막 태그 이후의 커밋을 읽는다.
   2. 사용자가 눈치챌 변경만 영어 한 문장씩 적는다.
   ```

   - `name`(필수) — 소문자 영문·숫자·하이픈, 64바이트 이하이며 폴더 이름과 같게 합니다.
   - `description`(필수) — 1,024바이트 이하. **AI는 이 설명만 보고 스킬을 쓸지 정합니다.** 무엇을 하고 언제 쓰며 어떤 비슷한 요청에는 쓰지 않는지 적으세요.
   - `when`(선택) — `platform: [windows]`, `provider: [openai]`처럼 쓰면 그 조건에서만 목록에 올라갑니다.
   - 본문은 비어 있으면 안 됩니다. AI가 이미 아는 일반론보다 결과, 선택 기준, 이 프로젝트만의 제약, 검증 방법을 적으세요.

3. **다시 읽기.** 설정 → 스킬 → **스킬 다시 읽기**를 눌러 목록에 나오는지 확인합니다. 머리말이 닫히지 않았거나 `description`이 없으면 위쪽에 경고 카드가 뜹니다.

**스킬 쓰기**

- AI가 대화 내용과 스킬 설명을 보고 필요할 때 스스로 골라 씁니다.
- 직접 지목하려면 입력창에 `$스킬이름`을 적습니다(예: `$release-notes 로 1.0.23 노트 써 줘`).
- 쓰지 않는 스킬은 스위치로 끕니다. 스킬이 너무 많아 목록 예산을 넘으면 일부가 AI에게 보이지 않으니, 그때도 안 쓰는 스킬을 끄세요.
- 플러그인이 가져온 스킬은 `<플러그인>:<이름>`으로 표시됩니다.
- 스킬은 AI에게 주는 지침이므로 **신뢰하는 출처의 것만** 쓰세요. 스킬이 도구 권한을 넓히지는 않으며, 승인 규칙(5장)은 그대로 적용됩니다.

### 트리거(매크로)

- **매크로** — 자주 쓰는 지시를 이름으로 저장합니다. 트리거가 발동하면 그 지시가 전달됩니다.
- **트리거** — 정해진 때에 자동으로 실행합니다. 유형은 **인터벌**(N초마다)과 **AI 응답 완료 시**입니다.
- 기능 전체는 사이드바의 **트리거**로 켜고 끕니다.

### MCP

외부 서비스의 도구를 붙입니다. **서버 추가**로 주소·헤더를 넣으면 시작할 때 자동 연결되고 도구가 합류합니다. 서버마다 **다시 연결 · 편집 · 삭제**, **사용(켜기/끄기)·신뢰(승인)** 를 정하고, 인증이 필요하면 로그인/로그아웃합니다. 조회만 하는 도구는 **읽기 전용**으로 표시해 허락 없이 쓰게 할 수 있습니다. 무언가를 바꾸거나 보내는 도구는 표시하지 마세요.

### 플러그인

스킬·MCP 서버·훅·에이전트를 한 묶음으로 설치합니다. Codex·Claude Code 플러그인 폴더(`.codex-plugin`·`.claude-plugin`)를 그대로 쓸 수 있습니다. **폴더에서 설치**하거나, **마켓플레이스**(Git 저장소나 폴더의 플러그인 목록)를 추가해 항목을 골라 설치합니다. 목록에 있다고 설치되지는 않습니다. Git 출처는 커밋으로 고정해 설치합니다. 플러그인은 코드를 실행할 수 있으니 신뢰하는 출처만 설치하세요.

### 캐릭터

먼저 말 걸기와 예약을 설정합니다(8장).

## 10. 알림과 백그라운드 작업

- **백그라운드 작업** — 오래 걸리는 명령·감시·도우미 작업은 기다리지 않고 뒤에서 돕니다. 끝나면 대화에 완료 카드(마지막 출력, 종료 코드, 걸린 시간)가 뜹니다.
- **시스템 알림** — 설정 → 일반에서 켜면 앱을 보고 있지 않을 때 알려 줍니다. 루미가 맡은 일의 완료·승인 대기도 알림으로 옵니다.
- **예약 실행** — 반복 예약과 재깨움은 **앱이 켜져 있는 동안**만 동작합니다. AI 연결이 아직 설정되지 않은 대화는 자동 실행을 건너뛰고 그 이유를 대화에 남깁니다.

## 12. 문제가 생겼을 때

| 증상 | 해 볼 것 |
|---|---|
| 앱이 안 열린다 | 로그(`%APPDATA%\LumiPilot\LumiPilot\data\log\app.log`)와 오류 기록(`data\CrashLogs`)을 확인합니다. 비정상 종료였으면 다음 실행 때 이유를 알려 줍니다. |
| 모델 목록이 비어 있다 | 설정 → API에서 키를 넣었는지 확인하고 사이드바의 **↻**를 누릅니다. |
| 대화를 보냈더니 연결 설정 창이 뜬다 | AI 연결이 아직 안 된 것입니다. 창에서 서비스·인증·모델을 고르고 **시작하기**를 누릅니다. |
| Claude/Gemini 구독 로그인이 안 된다 | 이 버전에서는 두 서비스의 구독 로그인이 꺼져 있습니다. API 키로 연결하세요. |
| 명령 실행이 안 된다 | Git for Windows가 필요합니다. 설치하면 자동으로 잡힙니다. |
| 브라우저가 안 열린다 | Microsoft Edge WebView2 런타임이 설치돼 있는지 확인합니다. |
| 처음 실행할 때 Windows 경고가 뜬다 | 배포본에 코드 서명이 없어 SmartScreen이 경고할 수 있습니다. [README](../README.ko.md#다운로드)의 SHA-256 확인으로 다운로드 무결성을 확인하세요. |
| Visual Studio 디버깅 조회가 안 된다 | `LumiPilotDebugBridge.vsix`를 Visual Studio를 모두 닫은 뒤 설치했는지, 출력 창의 "LumiPilot Debug Bridge"에 가동 줄이 있는지 확인합니다. 크래시 덤프 분석은 확장 없이도 됩니다. |
| Google 도구가 안 보인다 | 설정 → API에서 Google 계정을 연결합니다. 클라이언트 ID·시크릿과 리디렉션 주소를 등록해야 합니다. |
| 로그인이 필요한 사이트를 AI가 못 연다 | 앱 안 브라우저로 그 사이트를 열어 직접 로그인합니다. 내가 로그인한 상태를 AI도 그대로 씁니다. |
| 저장한 키를 못 읽는다 | 다른 계정·PC에서 만든 데이터입니다. 키를 다시 넣거나 다시 로그인합니다. |
| 답변이 중간에 잘렸다 | 너무 길어서 잘린 것입니다. 나눠서 다시 요청합니다. |
| 같은 동작을 반복하다 멈췄다 | AI가 같은 도구를 계속 반복해 스스로 멈춘 것입니다. 지시를 바꿔 다시 시킵니다. |
| 음성이 안 나온다 | OS TTS 방식이면 Windows의 음성 언어(ko-KR) 설치를 확인합니다. 음성 모델 방식이면 ElevenLabs 키와 크레딧을 확인합니다. |
| 사용량 초과 오류 | 잠시 뒤 다시 하거나 다른 모델·키로 바꿉니다. |

그래도 해결되지 않으면 [LumiPilot 공식 Discord](https://discord.gg/e3j5EnK3J)에서 묻거나 **lumipilothelp@gmail.com**으로 문의하세요. 버전, 시각, 권한 모드, 증상, 재현 절차를 함께 적어 주세요. API 키, 비밀번호, 대화 전체, 저장소 전체는 보내지 마세요.
