Personal data and data handling contact: lumipilothelp@gmail.com
Effective: from the date the release containing this document version is published. Operator: an individual developer (display name LumiPilot). If this notice changes, the document version is raised and you are asked to confirm again. This notice is not legal advice.

1. Data stored on the device
Default app data location: on Windows %APPDATA%\LumiPilot\LumiPilot, on Android /sdcard/Android/data/com.claude.claude_app/files/LumiPilot
The paths below are relative to this data location.
Session data such as conversations and tool results: JSON, WAL and related files under data/sessions
Record of acknowledging the notices before use: data/legal_notice_receipt.json. The acknowledged document version, language, full text and UTC time are stored on the device. This is not treated as blanket consent to personal data processing or as permission to run tools. If the notices change, you are asked to acknowledge them again.
Attachments, generated results, memory, settings, scheduled tasks and similar are also stored on the device depending on the feature. Separate files may be created at external paths specified by your code or tools.
Cookies, logins and web storage of the built-in browser: on Windows %LOCALAPPDATA%\LumiPilot\LumiPilot\WebView2, on Android the app's private internal storage
Execution logs: data/log/app.log and rotated logs. Logs currently rotate at about 8MiB per file, and the actual size may vary with factors such as the size of a single message.
Crash data: data/CrashLogs. Windows dumps may contain sensitive content that was in memory, such as conversations, files and credentials, so do not upload them publicly.

2. API keys and login information
API keys and supported OAuth and MCP secrets use a separate credential storage layer. Encrypted storage uses the user account's DPAPI on Windows and an app-specific key in the Android Keystore on Android. If encrypted storage of an API key fails, it is not stored in plain text instead.
This does not mean that all conversations, attachments, logs, general settings and user files are encrypted. It is not a security boundary that protects against programs running with the same user permissions, memory after decryption, or separate storage by external programs. Credentials copied to another device or account may need to be entered again or require a new login.

3. Information sent to models
Requests are sent to the AI provider you selected or the server you configured. Depending on the feature and how the context is built, a request may include not only the current question but also system instructions, earlier conversation and summaries, attachments, images and screens, files read, search results and tool results. Automatic titles, compaction, scheduled tasks and character features may also call models depending on settings and execution conditions.
Ollama and custom servers also follow the configured address. Choosing a local server does not by itself block external communication by later web, MCP or integration tools.

4. Transmissions by integrations, tools and the browser
Web search and page reading: search terms, URLs and request data may be sent to the search provider and the target site.
Google and other integrations: depending on the login, permission scope and tool calls, lookup targets, document, mail and calendar content, recipients and attachments may be sent to the service.
Mail, messages, Git push and uploads: real data may be sent to the specified recipients, repositories and servers. Retrieved results may also be included in later model requests.
MCP, custom tools and the shell: configured servers and programs may access arguments, the environment and files, and may communicate over the network on their own.
Image generation, voice and location features: depending on the feature used, request data such as prompts, reference images, utterance text, voice and coordinates may be sent to the provider.
Location lookup: only when device location is available (Windows location service, Android location permission) and the AI decides it needs your location and calls the tool, the app reads your coordinates and includes them in the model request. If location is unavailable or permission is denied, no location is looked up, and the app does not substitute an estimate from your IP address. No separate confirmation dialog is shown.
Model list lookup: if you use the NVIDIA or OpenCode provider, the app requests the public catalog models.dev without authentication to get model limits. The request does not contain your API key or conversations.
Built-in browser and HTML preview: visited sites and external resource servers may process ordinary web requests, cookies and similar.
Android permissions: the app may request the microphone (voice input), location (location features), all-files access (file tools in working folders) and notifications. Each permission is needed only when you use that feature, and you can deny or revoke it in Android settings. If you deny it, that feature becomes unavailable.
Recipients of any external request can see your IP address. Check your approval scope and automatic execution settings. Whether data is processed abroad, and the recipient's retention, training, deletion and pricing, depend on the provider or server you actually choose and its policies.

5. Collection by the developer and diagnostic data
Storage on the device must be distinguished from transmission to external AI and tools. "The developer does not receive it" does not mean "it is not sent externally". This version of the app does not automatically send usage statistics, conversations, errors or crash data to the developer. It has no feature that connects to a server run by the developer, and logs and crash data stay on the device only. The one exception is the new-version check: when the app starts and at least 20 hours have passed since the last check, it downloads one public file from the developer's release repository on GitHub (github.com/lumipilot/LumiPilot) and compares the version. The Windows app downloads latest.json from the latest release; the Android app downloads latest-android.json from the same repository through GitHub's file host (raw.githubusercontent.com). No conversations, settings or identifiers are sent, but as with any internet request GitHub can see the requesting IP address and the app name and version (User-Agent). You can turn this off under Settings > About; while it is off, the app makes this request only when you press "Check now". The built-in browser (WebView2), the operating system and Android speech recognition services and similar may collect information on their own, subject to those providers' policies.
Before sending logs or dumps for a report, first check the recipient, purpose, contents and retention period. Masking of secrets in logs does not guarantee that all personal data is removed. Review API keys, conversations, files, mail and screen content yourself and send only what is needed.
If you contact support by email, your sending email address, display name, message body and any attachments you add are passed to the mail service and received by the operator. Handling of support mail is separate from the app's local storage and transmission to AI providers. Send only the information needed to confirm, answer and reproduce the issue. Before sending another person's personal data or sensitive files, check that you have the right to provide them and that they are needed.
Support inquiry data is used only to confirm, answer and reproduce the issue, and is not used beyond that purpose or kept indefinitely just because you sent it. The operator (an individual developer) retains it for as long as needed to handle the inquiry and deletes it when handling is complete and it is no longer needed, unless retention is required by law. To request deletion, contact the same email address; after confirming your request, the operator deletes the data except where retention is required by law. Support mail is received through Google's Gmail, so Google processes the mail and may store it on servers abroad, including in the United States. See Google's Privacy Policy (https://policies.google.com/privacy) for Google's processing and retention.

6. Retention, deletion and transfer
Conversations, attachments and settings may remain until they are deleted by the relevant feature or cleaned up by the user. Logs, attachments and snapshots have feature-specific size limits, but bulk automatic deletion by date or complete deletion is not guaranteed.
Use the app's features such as deleting a session. To remove all local data on Windows, close the app and related processes, back up what you need, and then clean up the app data and built-in browser folders above. On Android, uninstalling the app also removes the app data folder, so back up anything you want to keep before uninstalling. Working folders modified by the app, backup and sync copies, and data held by external services must be managed separately.
Deleting a file is not the same as unrecoverable secure erasure of the storage medium. Data already sent to an external provider is not removed by local deletion in the app. Use that provider's deletion, logout and token revocation features.
When a support inquiry is complete and no longer needed, or after confirming a deletion request, the operator deletes the relevant mail and attachments under the operator's control, except where retention is required by law. Mail deleted in Gmail can remain in Trash for up to 30 days and can be permanently deleted from Trash. Google's policies may apply to its backups or retention required by law.

7. Processing relationships and contact
Whether the developer, users or external providers are personal data controllers or processors is determined by the actual purpose of processing, decision-making authority, contracts and data flows. Data being stored on the user's device or sent with the user's API key does not by itself always remove either party's obligations.
Processing abroad may occur through the AI provider, server, integrated service or MCP you choose, the models.dev model-list lookup, the GitHub update check, or Gmail support mail, among other paths. The GitHub update check may send your IP address and app name and version; GitHub processes these under its own policy (https://docs.github.com/site-policy/privacy-policies/github-general-privacy-statement). See sections 3–5 for information sent to models.dev and selected services. Check each provider's policy for its recipients, countries and retention periods. You can turn off update checks in settings; you can avoid other transmissions by not using the feature or provider or by not sending support mail. In that case, you cannot use that feature or receive an answer to your inquiry.
You can contact the operator at lumipilothelp@gmail.com to request access, correction or deletion of personal data in support inquiries, or with questions about data handling. The operator will confirm and handle requests in accordance with applicable law and retention obligations. This notice does not replace any required statutory notice or prior consent.
